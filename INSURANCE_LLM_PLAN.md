# Insurance Advisor LLM Plan

## Default Bank Choice

Use SBI/SBI General as the default implementation target:

- State Bank of India is the bank distribution context.
- SBI General Insurance is the insurance provider used for product knowledge.
- Treat SBI and SBI General as separate legal entities where relevant.
- Source of truth must be official pages and policy/prospectus PDFs.

The source config is swappable: `insurance_agent/config/sbi_general_sources.json`.

## Can We Fine-Tune A Model For This?

Yes, but do not start with RL. The model first needs domain behavior:

1. Ask the right questions before recommending.
2. Map user needs to suitable insurance categories.
3. Explain tradeoffs, caveats, exclusions, waiting periods, and underwriting.
4. Avoid unsuitable products.
5. Support Hindi, Hinglish, English, Tamil, Telugu, and later more regional languages.

The practical training order is:

1. **RAG baseline first**
   - Scrape official product pages and PDFs.
   - Use retrieval to ground answers in policy documents.
   - Measure whether a base LLM can ask the right questions and recommend safely.

2. **SFT**
   - Fine-tune on expert-style conversations.
   - Best for teaching tone, question flow, JSON output format, multilingual behavior, and recommendation structure.
   - This repo now creates SFT records in `data/insurance/insurance_sft.jsonl`.

3. **Preference tuning / DPO**
   - Use pairs: good recommendation vs premature/unsafe recommendation.
   - Best after SFT when the model knows the task but sometimes over-recommends or omits caveats.

4. **RLVR / rule-verified RL**
   - Use verifiable rewards:
     - asked required slots
     - recommended expected categories
     - avoided disallowed categories
     - included caveats
     - valid JSON
     - cited official source ids
   - This is viable because insurance advice has rule-checkable parts.

5. **Human review**
   - Required for final suitability logic, compliance phrasing, and regulated product claims.

## Eval Data To Justify Fine-Tuning

Create eval cases before training. Each case should include:

- profile language
- age
- city
- family size
- dependents
- existing cover
- budget band
- needs
- constraints
- expected categories
- unsuitable categories
- must-ask slots

Metrics:

- ask-slot recall
- expected-category recall
- unsafe-category rate
- JSON/tool-format validity
- caveat rate
- citation/source-id presence
- multilingual pass rate by language

If a base model has low ask-slot recall or high unsafe-category rate, you have a concrete motivation to fine-tune.

## Data Creation Strategy

Use three data types:

1. **Grounding data**
   - Official pages and PDFs scraped by `scripts/scrape_insurance_sources.py`.
   - Store chunks in `data/insurance/source_chunks.jsonl`.

2. **SFT conversation data**
   - Generated by `scripts/build_insurance_dataset.py`.
   - Includes:
     - ask-clarifying-question examples
     - personalized recommendation examples
     - refusal/correction examples for premature recommendations

3. **Eval data**
   - Generated to `data/insurance/insurance_eval.jsonl`.
   - Kept separate from SFT data.

## Commands

Build seed SFT/eval data:

```bash
python3 scripts/build_insurance_dataset.py
```

Scrape official sources:

```bash
python3 -m pip install pypdf
python3 scripts/scrape_insurance_sources.py
```

Train LoRA:

```bash
python3 -m pip install "transformers>=4.41" "datasets>=2.19" "trl>=0.9" "peft>=0.11" accelerate bitsandbytes
python3 scripts/train_insurance_lora.py \
  --model Qwen/Qwen2.5-1.5B-Instruct \
  --dataset data/insurance/insurance_sft.jsonl \
  --output-dir outputs/insurance-advisor-lora
```

Evaluate predictions:

```bash
python3 scripts/evaluate_insurance_agent.py \
  --eval data/insurance/insurance_eval.jsonl \
  --predictions data/insurance/predictions.jsonl
```

Prediction JSONL format:

```json
{"case_id":"family_health_hinglish","response":"{\"recommendation\":[{\"category\":\"health\"}],\"next_step\":\"Check official policy wording and premium quote.\"}"}
```

## What Not To Do

- Do not scrape non-official aggregators as source of truth.
- Do not train on fake premiums.
- Do not let the model make final eligibility or underwriting decisions.
- Do not recommend investment-linked insurance as a default unless the user explicitly asks and suitability checks are strict.
- Do not skip disclaimers about policy wording, exclusions, waiting periods, underwriting, and premium quote.
